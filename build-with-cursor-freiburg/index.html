The Paradigm Shift

How we get unstuck has changed.

Three eras, each with a different default reflex when you don't know how to do something.

01
Pre-AI
Docs, StackOverflow, forums, blog posts. You search, read, synthesize, then write every line yourself.
02
AI, pre-agentic
Ask a chatbot, copy the snippet, paste it in. Faster answers — but zero project context and no memory between prompts.
03
Agentic
Agents with harness — they see your full codebase, respect your conventions, and coordinate multi-file changes semi-autonomously on your behalf.
Build with Cursor · Freiburg05 / 34
Keep it relatable. Pre-AI: everyone lived on StackOverflow and official docs. AI copy-paste era: faster answers but you still had to glue everything together manually with no project awareness. Agentic: the tool understands your codebase, your rules, and can act across files — you shift from writing to reviewing.
×
The Paradigm Shift

What changes day-to-day.

Two concrete shifts in how you spend your time.

01
Reading > Writing
Your daily ratio flips. You spend most of your time reviewing diffs the agent produced, not drafting them. The skill that matters: spotting what's wrong in a proposed change quickly — not typing it out.
02
Iteration gets cheap
Generating a prototype takes 30 seconds, not 2 hours. So you try three approaches before committing to one. Decisions become empirical — prove it, don't debate it.
Build with Cursor · Freiburg06 / 34
Reading > Writing: the most surprising shift for newcomers. You go from "blank page → done" to "review agent output → accept/reject/refine." It's closer to code review than code authoring. Iteration cost: when trying something is nearly free, you stop over-planning and start experimenting. This changes team dynamics too — fewer long design meetings, more quick spikes.
×
The Paradigm Shift

Context is the new skill.

The hard part isn't "how to implement X" — it's giving the agent the right information so it gets X right on the first pass.

Scope the prompt
Attach relevant files, reference specific functions. Vague prompts produce vague code.
Know what exists
Awareness of libraries, APIs, and patterns you can ask for beats memorising their syntax. Breadth over depth.
Harness
The model is only one part. Context, instructions, and tools are what make the agent useful.
Build with Cursor · Freiburg07 / 34
This is the most actionable point in the section. The bottleneck moves from "can I write this?" to "can I describe this clearly enough?" Three sub-skills: (1) scoping — attach the right files, don't dump the whole repo; (2) rules — codify your conventions so the agent follows them without being told each time; (3) breadth — knowing a library exists means you can ask for it, even if you don't remember the API.

Cursor Fundamentals

Harness = the layer around the model.

In Cursor, the agent is not just a chatbot. The harness combines instructions, tools, and the model so it can act on your codebase.

01
What it is
A runtime wrapper around the model. It adds the prompt, the working context, and the actions the agent is allowed to take.
02
How Cursor sets it up
Your chat, attached files, and rules become instructions. Built-in search, edit, terminal, browser, and MCP access become tools. The model comes from the selector in chat.
03
How you influence it
Be specific, attach the right context, choose the right mode/model, and codify repeatable guidance in rules or skills. If the context gets noisy, start a fresh chat.
Your leverage is upstream. You usually do not change the harness directly. You steer it through intent, context, and configuration.
Build with Cursor · Freiburg17 / 34
Use the official language from the transcript here: the harness is instructions, tools, and model. Then make it practical. In Cursor, users shape the harness indirectly through prompts, attached context, rules, skills, and model choice. The key teaching point is that better steering happens before generation, not after.

Cursor Fundamentals

Indexing gives the agent a usable map.

Cursor combines exact search and semantic search so you can ask natural questions and still reach the right files quickly.

01
Exact matches
When you know a symbol, file name, or literal string, the agent uses fast code search to locate it precisely.
02
Meaning-based search
When you only know the intent, semantic search can still surface relevant code, even if the words do not match exactly.
03
Context discipline
Explore sub-agents can search large codebases in a separate context and return only the findings that matter.
Practical default: let Cursor index in the background, then ask plain-language questions before you start editing.
Build with Cursor · Freiburg18 / 34
Keep this practical. The important point is not the implementation detail, but the outcome: exact search for known symbols, semantic search for intent, and sub-agents for better context control in larger repos.

Cursor Fundamentals

Chat modes shape the workflow.

Use the lightest mode that fits the job: understand first, plan second, then edit or debug with evidence.

01
Ask
Read-only exploration for architecture questions, codebase navigation, and quick explanations.
02
Plan
Research the codebase, clarify requirements, and draft a step-by-step approach before changing files.
03
Agent
Make edits, run tools, and verify results when the task is already well-scoped.
04
Debug
Collect runtime evidence, test hypotheses, and work toward a targeted fix instead of guessing.
Good habit: switching modes early usually improves output more than adding another vague prompt.
Build with Cursor · Freiburg19 / 34
Frame chat modes as operating modes, not marketing labels. Ask is for understanding, Plan is for structuring work, Agent is for execution, and Debug is for evidence-driven investigation.

Tools

Model

Real-World Workflows

Keep the context window sharp.

The agent's working memory is powerful but finite. Guard it.

01
New feature
Start a new conversation instead of dragging old context along.
02
Going off track
Reset early when the agent starts guessing or repeating mistakes.
03
Large codebase search
Delegate exploration to sub-agents instead of bloating the main thread.
04
Focused return
Keep only the findings you need and continue from there.
Build with Cursor · Freiburg22 / 34
Context management is one of the biggest leverage points. New feature, new chat. If the thread gets noisy, reset fast instead of trying to repair a bad prompt chain.
×
Real-World Workflows

Understand before you change.

Agents that skip comprehension create redundant code and tech debt.

ASK → GREP + SEMANTIC SEARCH → ARCHITECTURE DIAGRAM → EDIT
Exact match
Use grep, ripgrep, or instant grep when you know the symbol, string, or file.
Meaning-based search
Use semantic search when you know the intent, not the literal wording in code.
Visualise first
Ask for a Mermaid diagram to understand services and data flow before editing.
Build with Cursor · Freiburg23 / 34
This is the workflow for unfamiliar code. Ask questions in plain language, let the agent search by exact match and meaning, then use a diagram if the system is still fuzzy.
×
Real-World Workflows

Git is the bedrock of AI-assisted development.

Agents increase output. Version control makes that speed reversible, reviewable, and safe to share.

01
Branch first
Give experiments a safe place to run before the agent starts changing files.
02
Commit checkpoints
Save small, meaningful milestones so you can compare, revert, or recover quickly.
03
Review the diff
Inspect what changed in Git, not only what you asked for in the prompt.
04
Merge with checks
Use PRs, CI, and human review to turn fast iteration into reliable delivery.
Build with Cursor · Freiburg24 / 34
Place Git right between understanding and execution. The point is not Git for Git's sake, but Git as the safety system that makes AI-assisted iteration practical in a team.

Real-World Workflows

Plan first, build second.

Move through modes as clarity increases: understand → design → execute.

01
Ask mode
Explore the codebase and understand what already exists.
02
Plan mode
Shift+Tab, describe intent, answer questions, and trim the plan.
03
Agent mode
Build the scoped plan and let the agent verify each step.
04
Iterate
Paste screenshots, tighten requirements, and refine the result.
Key habit: be explicit about what to include and what to leave out in the first pass.
Build with Cursor · Freiburg25 / 34
The sequence matters here. Ask first to understand, Plan second to structure, Agent last to execute. That produces better output than jumping straight to generation.

Real-World Workflows

Debug with evidence, not guesses.

Same fundamentals whether a human or an agent does the work.

Simple bugs
Paste the stack trace directly when the failure is obvious and localised.
Complex bugs
Switch to Debug mode so the agent can gather runtime evidence before fixing.
Extra leverage
Try multiple models and pull MCP data from tools like Sentry or your database.
REPRODUCE → MINIMAL CASE → ISOLATE → HYPOTHESIZE → INSTRUMENT → FIX → TEST
Build with Cursor · Freiburg26 / 34
Use the classic debugging loop. The important idea is that agents should collect evidence first on the hard bugs, not just guess from a vague description.

Real-World Workflows

Review AI code like you'd review a colleague's.

AI-generated code can compile, pass tests, and still be subtly wrong.

01
Self-review
Run a first pass locally and use Find Issues to catch obvious misses.
02
Semantic commits
Split large diffs into reviewable commits before opening the PR.
03
AI review
Use BugBot or a similar reviewer for another regression pass.
04
Human review
Bring teammates in only after the noisy issues are already gone.
Bar to merge: if you do not understand the fix, keep asking questions until you do.
Build with Cursor · Freiburg27 / 34
Make the point that review standards do not change just because the code was AI-generated. The review loop still matters, and maybe matters more.

Real-World Workflows

Tests are the agent's guardrails.

High-quality tests let agents move faster without introducing regressions.

Write with the feature
Do not wait for something to break before adding coverage.
Use existing infra
Point the agent to current test patterns so it fits the codebase.
Fuzz broadly
Let agents click through variants and return screenshots or videos.
CI is the gate
Every PR should rerun the checks automatically before merge.
Compounding gain: faster tests matter more when agents run them dozens of times a day.
Build with Cursor · Freiburg28 / 34
Testing is how you safely increase autonomy. Strong tests and faster CI turn agent output from risky to manageable.

Real-World Workflows

Teach the agent how your team works.

Two layers of customization, like onboarding a new teammate.

Rules
Always-included markdown for build commands, conventions, and canonical patterns.
Skills
Load specialized workflows only when relevant, including scripts and reusable processes.
Plugins and CLI
Package rules, skills, and MCPs together, then let agents use tools like gh or docker.
Keep it minimal: too many rules waste context and make the agent less reliable.
Build with Cursor · Freiburg29 / 34
Rules are always on. Skills are pulled in only when needed. The advice from the transcript is to keep rules short and move occasional workflows into skills.

Customization

Rules: write once, apply always.

Drop a file in .cursor/rules/ and every prompt inherits your conventions.

.cursor/rules/components.mdc
---
globs: src/components/**/*.tsx
alwaysApply: false
---

- Use named exports, not default exports
- Co-locate styles in a module CSS file next to the component
- Keep components under 200 lines. Extract subcomponents into the same
  directory when a file grows beyond that
- Prefer composition over prop drilling. Pass children or render props
  instead of threading data through multiple layers
