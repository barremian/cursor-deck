Layer 01 · Rules
01  Before

Cursor Rules.

Paste once. Cursor respects them always.

01
Create the folder
.cursor/rules/
02
Inside, create the file
security.mdc
03
Paste the rules
→
security.mdc
---
description: Security baseline
alwaysApply: true
---

# Auth
- Validate the server session,
  NEVER trust the client.
- user.id == session.user.id
- Secrets: process.env, never
  hardcoded.
- JWT: exp <= 15m, explicit alg.

# Prompt injection
- NEVER interpolate user input
  into system prompts.
- Separate role:system / role:user.

Layer 02 · Prompt
02  During

A prompt you can copy.

Paste it before requesting sensitive features: login · payments · uploads · auth.

Before writing the code:
1.
List the 5 most common security risks for this type of feature.
2.
Show me how you mitigate them (library, validation, config).
3.
Only then, write the code.

If you have Rules, append "…following security.mdc" at the end.

Demo · The victim

The victim app.

A real NestJS login, generated with no thought given to security.

backend/src/auth/auth.service.ts
async login(username: any, password: any) {
  // Input goes straight to Mongo — NoSQL injection
  return this.db.collection('users')
    .findOne({ username, password });
}

async register(username: any, password: any) {
  // Plaintext password, no bcrypt
  await this.db.collection('users')
    .insertOne({ username, password });
}
3 bugs in 10 lines
01
NoSQL Injection
02
Plaintext passwords
03
No input validation
